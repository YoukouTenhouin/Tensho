# English lookup with Simplified Chinese explanations: implementation handoff

Research completed 2026-10-07 for [#45](https://github.com/YoukouTenhouin/Tensho/issues/45), after [analysis #43](https://github.com/YoukouTenhouin/Tensho/issues/43) and [dictionary #44](https://github.com/YoukouTenhouin/Tensho/issues/44). Repository inspected at `3d00f4c`. This is an implementation-ready **bounded lexical reading aid**, not a production release or a claim of exhaustive English grammar. The user requested English lookup for a learner using Simplified Chinese. The existing Chinese interface alone does not provide Chinese definitions. [Current catalog](../../src/providers/catalog.ts), [existing interface behavior](../i18n.md), [provider findings](english-provider-contract.md).

## Readiness decision

Proceed with an English profile (`eng`) whose default explanation preference is `zh-Hans`. Recommend bundled licensed WordNet 3.0 indexes/exceptions for possible lexical bases, a small extension-authored function-word supplement, and official Chinese Wiktionary for source-authored Simplified Chinese articles. No API key, paid account, external executable or self-hosted service is required. This explicitly extends the original hosted-provider plan to bundled static analysis data for English; Latin's established providers remain independent. This is the proposed implementation design recorded by this research, with production implementation separately authorized. [Provider acquisition, license and limitations](english-provider-contract.md), [original planning constraints](https://github.com/YoukouTenhouin/Tensho/issues/1).

Readiness passes because there is an acquired and hashed analysis source with understood limitations, an official accountless dictionary API with observed provider-native Simplified Chinese output, a measured packaging path, and a concrete adapter/result-model plan. There is no outstanding provider-research dependency for this bounded scope. Browser performance, production optional-permission prompts, interruption, Chinese accessibility and linguistic fixture checks remain **implementation acceptance**, with explicit gates below. [WordNet evidence](english-wordnet-probes/provider-results.json), [dictionary observations](english-wiktionary-probes/provider-results.json), [Edge evidence](english-wiktionary-probes/edge-access-results.json).

The supported workflow is selected or manually entered English words, possible bases where supported, and on-demand Chinese dictionary articles. Multiword selection continues to offer individual words. General phrase lookup, contextual parsing, phrasal-verb discovery, pronunciation playback, machine translation, exhaustive morphology and an offline dictionary are outside this first increment. Hyphenated words and contractions remain whole selected forms. Dictionary gaps such as the sampled missing `he's` page are visible; they do not trigger English explanations or another language. [Orthographic offering](../../src/core/input.ts), [dictionary fixtures](english-wiktionary-probes/provider-results.json), [role/language isolation](../adr/0001-separate-analysis-and-dictionary-roles.md).

## Measured evidence and limits

- The official WordNet archive is 11,537,239 bytes; the derived spelling/POS/exception asset is 2,347,086 JSON bytes and 698,907 gzip bytes. Twenty-seven lexical probes expose useful irregular bases and ambiguity, plus function-word gaps and false-positive suffix paths. The derived asset is not yet shipped or benchmarked in Edge. [Evidence and reproduction](english-provider-contract.md#acquired-artifact-and-executable-evidence).
- Fifteen serial bounded API requests tested thirteen English spellings, a non-English page control, and a second Chinese variant of `book`. All returned HTTP 200 JSON; two returned API `missingtitle` (`he's`, artificial unknown). `水` supplies no English section. `gift` and `go` contain several languages, requiring English-section isolation. `Wasser` unexpectedly has an English surname section: capitalization and apparent foreign origin cannot determine lookup language. [Responses](english-wiktionary-probes/provider-results.json).
- `book` revision 9744765 supplies `预订` with `variant=zh-hans` and `預訂` with `variant=zh-hant`. This is provider-native script conversion, not extension translation. `I`, `the`, `is` and `don't` have English sections even where WordNet gives poor or no analysis. [Extracted text](english-wiktionary-probes/extraction-results.json).
- Metadata-only page/revision resolution followed by `parse&oldid=...` retrieves the same revision. One live request from a disposable headless Edge 154.0.4258.37 MV3 worker with a research pregrant returned the Simplified Chinese entry. The English Wiktionary origin was ungranted. This does not verify production optional permission prompts, denial or revocation. [Resolution evidence](english-wiktionary-probes/resolution-results.json), [Edge result](english-wiktionary-probes/edge-access-results.json).
- A research-only parse5 extractor retains English-section paragraphs and safe links, excludes other language sections and active/media/style elements, and passes the retained cases plus controlled hostile markup. This establishes a concrete inert extraction seam; it does not replace a production parser's validation and browser rendering tests. [Extractor](english-wiktionary-probes/extract.mjs).

These are deliberately small correctness and integration probes, not a representative coverage benchmark, request-quota measurement or availability guarantee. Chinese Wiktionary is a community dictionary with uneven coverage; richer licensed learner dictionaries remain future alternatives. [Alternatives](english-provider-contract.md#alternatives-assessed).

## Configuration and installation contract

The catalog must add `eng`, the bundled analyzer and the hosted dictionary. The analyzer declares `structuralAnalysis: true`, no explanatory languages, and `origins: []`; the dictionary declares explanation language `zh-Hans` and only `https://zh.wiktionary.org/*`. Existing role eligibility already permits structural-only analysis when only the dictionary supports the explanation preference. Do not advertise English dictionary explanations until an integrated provider supplies them. [Configuration roles](../../src/core/configuration.ts), [ADR 0002](../adr/0002-explanation-preferences-and-provider-eligibility.md).

The current `ConfigurationStore` accepts valid saved schema-1 settings verbatim, and `editSettings` requires every integrated language. Adding a catalog entry alone leaves existing installations without `eng` and prevents ordinary saves. Implement an additive, idempotent migration before exposing settings: retain selected lookup language, existing profiles/provider order/options/disabled choices, and independent interface preference; append only the absent English profile using its declared defaults; durably write a fresh configuration revision before publishing. Never reset existing Latin or Sanskrit settings. A failed write must leave the prior durable settings intact and surface a recoverable error. Repeat startup must not change the revision again. [Store and validation source](../../src/core/configuration.ts), [worker settings boundary](../../src/browser/worker.ts).

Fresh installation retains Latin/English as the global lookup default. Selecting English uses its saved Chinese preference; explicitly choosing a Chinese interface remains independent and does not route providers or translate definitions. Disabling all English providers preserves the preference as unavailable. Editing another profile does not activate English. [Existing defaults and eligibility](../../src/core/configuration.ts), [interface independence](../i18n.md).

## Result and analysis contract

Add an explicit selected-form candidate kind to the shared result model, with backward-compatible defaults for retained Latin records. Distinguish `lemma` candidates from `surface-form` candidates rather than presenting every spelling as a discovered base. A surface-form candidate carries an exact display spelling, a separately recorded lookup key, unknown stable lemma identity, no invented interpretations/short meanings, and a localized label such as “Selected form” / “所选词形”. It remains eligible for lazy dictionary resolution even when structural analysis is unavailable. Update result rendering, routing and retained-record validation together. [Current candidate shape](../../src/core/lookup.ts), [retained identity checks](../../src/core/reading-record.ts), [dictionary uncertainty](../adr/0005-preserve-uncertainty-in-dictionary-mapping.md).

Preserve original selection and UTF-16 offsets. Permit only declared English orthographic inputs before consulting providers; mixed unsupported script and punctuation-only input must not become English matches. For lookup keys only, document NFC and curly-apostrophe normalization as an explicit transform; retain the original spelling. Query an exact case-preserved surface form, and use case-folded WordNet proposals only with their transformation evidence. Never replace `I` with a lowercase letter noun as its asserted analysis. Review the supplement first for known function words; disclose other letter/name alternatives as proposals. Do not generically strip possessives or split contractions into unrelated candidates. [Input preservation](../../src/core/input.ts), [observed WordNet traps and supplement specification](english-provider-contract.md#small-supplement-and-selected-form-lookup).

Retain exact lexical bases, documented exception bases and every index-validated conservative suffix proposal, with source and evidence. Group duplicate paths to the same spelling/POS without losing evidence; different POS remain available. WordNet POS and extension rule descriptions do not establish contextual tense, person or sense. No short Chinese meanings are generated from English WordNet glosses. The supplement contributes reviewed grammatical facts, not copied dictionary definitions. Translate extension-authored standardized labels and proposed interpretation labels into the chosen interface language; preserve source-authored dictionary prose unchanged. [Morphology contract](english-provider-contract.md#analysis-semantics), [grammar display boundary](../../src/browser/grammar-view.ts), [ADR 0002](../adr/0002-explanation-preferences-and-provider-eligibility.md).

Use the acquired archive/hash and an explicit member allowlist to deterministically generate packaged lexical data. Include the complete Princeton license and source/version attribution. Lazy-load bounded packaged data through the worker on first English use, share that load, and validate the final artifact hash/schema. Local lookup must check cancellation, configuration identity and the existing action deadline; corrupt/missing asset is technical failure, not no-match. Empty-origin providers are explicitly permitted without invoking native host permission checks on an empty list. Bundled analysis does not imply offline dictionary access. [Artifact provenance](english-provider-contract.md#acquired-artifact-and-executable-evidence), [provider-chain checks](../../src/core/provider-chain.ts), [request limits](../../src/core/requests.ts).

## Lazy Chinese dictionary adapter

Resolution uses the official endpoint `https://zh.wiktionary.org/w/api.php`, `action=query`, `titles=<lookup key>`, `redirects=1`, `prop=revisions`, `rvprop=ids`, `format=json`, `formatversion=2`. Validate namespace zero, resolved title, page ID and latest revision ID; retain redirects as provenance, never as proof of lemma/sense identity. Produce a learner-selectable possible page entry. The article ID must be namespaced by provider/page/revision; it is not a WordNet lexeme ID. Metadata establishes a possible page, not an English article or a match for a particular grammatical reading. Keep `automaticSelection: null`, unverified correspondence and non-exhaustive resolution. [Observed query→parse flow](english-wiktionary-probes/resolution-results.json), [official parse documentation](https://www.mediawiki.org/wiki/API:Parsing_wikitext), [ADR 0009](../adr/0009-lazy-dictionary-retrieval-and-fallback.md).

Retrieval after “Read entry” uses `action=parse`, `oldid=<resolved revision>`, `prop=text|revid`, `format=json`, `formatversion=2`, `variant=zh-hans`, `disableeditsection=1`. Verify page/revision identity and returned structure. Select only the exact English language heading (`英语` / `英語`) within the parser root and its content until the next top-level language heading, retaining all English etymologies/POS/senses/examples/usage paragraphs. Do not use the first language section or equate a page title with English identity. The research heading extractor handles current wrapper and direct-heading forms; production must reject incompatible structure rather than scrape arbitrary prose. `prop=sections` is deprecated; it is unnecessary for this boundary. [Fixtures/extractor](english-wiktionary-probes/extract.mjs), [API documentation](https://www.mediawiki.org/wiki/API:Parsing_wikitext), [native variant parameter](https://www.mediawiki.org/wiki/API:Main_module).

Convert the selected section to extension-owned paragraphs and validated HTTPS links through an inert parser. Omit scripts, styles, embedded media, edit controls and site furniture; do not load referenced images/audio/modules or inject provider HTML. Keep pronunciation text where supplied, but do not promise playback. Render the complete supplied English section within existing article bounds, including English example text inside the Chinese article. Include contributor attribution, revision/source/history links, CC BY-SA 4.0 license link, and an extraction notice. Provider-native Simplified Chinese rendering is retained verbatim. [Research safe-content path](english-wiktionary-probes/extract.mjs), [ADR 0008](../adr/0008-dictionary-articles-as-text-and-links.md), [Chinese article license footer](https://zh.wiktionary.org/zh-hans/saw), [Wikimedia licensing terms](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use#7._Licensing_of_Content).

HTTP 200 is insufficient for success. An API `missingtitle`, a query missing page, or a valid page with no English section is a provider-scoped unavailable entry, never evidence that English lacks the word. Preserve unresolved mapping and its reason; avoid claiming corpus-wide confirmed absence. A malformed payload, unexpected structure, API operational error, protection page, HTTP failure, or oversized response is technical failure. A Chinese article with no useful translated gloss remains an explicit provider limitation; do not silently fetch English prose. References to another spelling, such as `ice-cream → ice cream`, remain readable links without automatic recursive requests. [Misses and alternate spelling](english-wiktionary-probes/provider-results.json), [fallback rules](../adr/0001-separate-analysis-and-dictionary-roles.md).

## Access, resource and lifecycle contract

The worker/options currently expose only Latin service-access origins and a `latinAccessDecision`. Add an English dictionary access control and provider-specific decision state, leaving reading-site access separate. Granting access sends no word. No dictionary operation may dispatch before its declared origin is granted; recheck at dispatch/completion and cancel on revocation. The packaged analyzer needs no network grant. [Current service-access boundary](../../src/browser/worker.ts), [options permission request](../../src/browser/options.ts), [revocation plumbing](../../src/core/provider-access.ts).

Send only the chosen spelling/lookup key in resolution and the revision ID in retrieval. Use credential-free requests and a descriptive `Api-User-Agent` containing the repository contact link. Do not use a proxy or evade protections. Keep existing two-operation concurrency, 15-second request timeout, 30-second learner-action deadline, 1 MiB decoded article bound, selection limits and 6 MiB session-results budget. HTTP 429/503 and API rate/maxlag errors end the attempt with explicit retry; no immediate automatic retries or service-wide quota assumptions. [Request/input/session bounds](../../src/core/requests.ts), [input limits](../../src/core/input.ts), [session budget](../../src/core/session-results.ts), [operator user-agent policy](https://foundation.wikimedia.org/wiki/Policy:Wikimedia_Foundation_User-Agent_Policy), [API etiquette](https://www.mediawiki.org/wiki/API:Etiquette).

Retain only results under their existing tab/document/configuration/lookup/explanation identity. Preserve lazy articles, expansion and reading position through worker suspension; clear on existing navigation/restart boundaries. Persist static packaged lexical data only as an installation asset, never selected text or fetched Chinese articles outside session storage. Do not persist a Chinese page/article cache by borrowing the Latin index cache. [Existing identity/storage contracts](../../src/core/reading-record.ts), [session-only results](../adr/0007-session-only-reading-results.md).

## Implementation sequence and acceptance

1. **English profile and analysis:** additive settings migration; licensed deterministic asset; conservative analysis/supplement; selected-form result model and Chinese/English labels; retained-record compatibility. Meaningful checks cover old-install migration, failed-write recovery, no unintended default change, all 27 WordNet fixtures, `I`/`the`/contractions, ambiguous bases, original spelling and unsupported inputs. Record packaged load time/memory in Edge and retain Latin regressions.
2. **Chinese dictionary integration:** official metadata→revision adapter, English section boundary, inert complete-text extraction, contributor/license attribution, provider-specific optional access. Checks cover retained positive/missing/no-English/multilingual/alternate-spelling fixtures; controlled incompatible and hostile payloads; HTTP200 API errors, oversize, timeout, cancellation and revocation; no dictionary request until explicit actions and grants; no cross-language or English-explanation fallback.
3. **English reading acceptance:** integrate both routes and run `npm run check`; isolated native Edge tests cover English selection→possible bases/selected form→chosen Chinese article, existing-user upgrade, per-tab/session restoration, stale language changes, permission denial/revocation and full readable inert rendering. Chinese interface/speech checks cover base-form ambiguity, unavailable analysis, selected-form lookup, missing Chinese article and recovery. Run speech only with `python3 tests/native/silent_speech.py -- <command>`; shared-desktop windows, if needed, must use verified HDMI-A-1 placement.

Each production feature ticket follows the repository's `<ticket>-dev` → `<ticket>-reflow` workflow, identical final trees, required tests, and PR to `master`. This research changes no production code and grants no production delivery acceptance. [Workflow](../../AGENTS.md), [desktop/speech instructions](../../AGENTS.md), [existing test commands](../../README.md).

The public reports and issue resolution comments are the handoff. Research blockers are resolved for this scope; ECDICT rights, offline Chinese data, and commercial provider contracts are alternatives, not dependencies of the selected route. If production testing reveals a provider format/access failure, open a concrete blocker rather than broadening the service or explanation language silently.
