# Sanskrit input capabilities and display transliteration

Sanskrit input support follows the native capabilities of configured providers, allowing different providers to accept different notations without requiring extension-side input conversion. Providers incompatible with the input notation are excluded before applying configured order and ADR 0001's technical-failure-only fallback rules; having no compatible provider is an unsupported-input condition, not a valid no-match result. This preserves access to provider-supported notations beyond Devanāgarī without making a shared input converter a prerequisite.

Sanskrit results include IAST alongside Devanāgarī. The extension may transliterate for display while preserving the provider's original text: this reading aid is independent of input conversion and does not require providers to supply both display forms. Verified notation conversion is also allowed when handing candidate lemmas from an analyzer to a dictionary, preserving the original lemma and provider identity; this does not relax native input compatibility for the learner's selected text. These decisions were agreed during [issue #8](https://github.com/YoukouTenhouin/Tensho/issues/8)'s design interview; integration feasibility remains unresolved.
