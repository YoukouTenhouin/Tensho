# Interface translations

Settings → Interface → Interface language saves immediately. Browser default follows the browser UI language; English and 简体中文 are explicit overrides. The Chinese interface calls the product 天书. Lookup language and per-language explanation preferences are independent: Latin lookup and English explanations remain the fresh defaults in either interface.

Automatic selection uses `chrome.i18n.getUILanguage()`, rather than the browser's preferred website-content languages. English variants use English; Chinese tags whose likely script is Hans (including zh, zh-CN and zh-SG) use Simplified Chinese. Traditional Chinese and other unsupported languages fall back to English. Explicit overrides survive browser restarts. Choosing Browser default restores automatic selection.

The separate `interfaceLanguage` local-storage key stores `auto`, `en`, or `zh-Hans`. Existing lookup settings need no migration. Interface saves do not change lookup identity, configuration revision, provider routing or requests. Open extension pages redraw labels while retaining results, articles, drafts, focus and reading position. Browser restart still clears reading results according to the existing session contract.

## Catalogs and rendering

`public/_locales/en/messages.json` and `public/_locales/zh_CN/messages.json` are the shared Chrome-format catalogs. The build copies them for manifest localization and bundles them for runtime explicit overrides. Chrome's `getMessage` always uses its browser locale, so extension-owned pages instead use the small translator in `src/i18n/messages.ts`. Missing translated messages fall back to English. Manifest metadata and shortcut descriptions follow the browser locale; the context menu and action tooltip follow the selected interface preference.

Use `t('messageId', { namedParameter: value })` for displayed text and `message('messageId', { namedParameter: value })` for notices/errors crossing core, worker and session boundaries. Catalog parameters have Chrome's `$name$` syntax and a corresponding `placeholders` declaration. Parameters are substituted once and numeric values use locale-aware formatting. Insert the result through `textContent` or a text attribute, never `innerHTML`. Static elements use `data-i18n` and `data-i18n-aria-label`, `data-i18n-title` or `data-i18n-placeholder`.

Retained notices carry stable message identifiers alongside diagnostic text. Existing records remain readable; known status/failure kinds and structured grammar localize at display time. Unclassified legacy notices use a generic localized recovery message in Chinese. Source-authored prose, grammatical values, proper source names and attribution remain as supplied. Grammatical field labels are localized from the retained structured fields; plain interpretations remain a fallback when structured data is absent.

Locale changes cancel queued obsolete announcements and establish a new dictionary-announcement baseline, rather than announcing retained completions as new work. Provider draft localization preserves its original configuration revision and unsaved edits.

## Add a translation

1. Copy the English catalog into a Chrome-supported `_locales/<locale>/messages.json` directory. Translate messages while preserving message IDs and named placeholders. Keep manifest strings free of runtime substitutions.
2. Import the new catalog and register its BCP 47 interface locale, autonym, translation selection and browser-locale matching in `src/i18n/messages.ts`. Extend preference validation in `src/i18n/preference.ts`. The Settings selector uses the registered autonyms.
3. Extend catalog completeness/placeholder and matching tests in `tests/i18n.test.ts`; add a browser acceptance case for the new locale. Run `npm run check`. No additional runtime dependency or translation service is needed.

English native regressions set the language of their disposable browser to English. Chinese acceptance deliberately sets it to Chinese:

```sh
node scripts/build.mjs --recovery
python3 tests/native/session_workflow.py --i18n --output /tmp/tensho-i18n
python3 tests/native/silent_speech.py -- python3 tests/native/orca_workflow.py \
  --runtime /tmp/tensho-orca-runtime/usr --i18n --output /tmp/tensho-orca-chinese
```

The speech runner requires the documented Orca runtime prefix and always refuses to run outside the silent wrapper. It records native speech events, not physical pronunciation quality.
